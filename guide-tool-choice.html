Choosing a tool_choice setting

A five-minute guide to the four settings, a two-question method for choosing between them, and the traps that exam questions are built on. There are ten drill questions at the end.

The one idea

tool_choice answers two things: must Claude call a tool, and if so, does it get to choose which one?

The four settings

SettingWhat Claude must doCan it reply in text?Who picks the tool?
autoNothing is forced. This is the default when tools are present.YesClaude
anyCall one of the tools.NoClaude
A named toolCall that exact tool.NoYou
noneCall no tools.Yes, text onlyNobody

In an API request they look like this:

"tool_choice": {"type": "auto"}
"tool_choice": {"type": "any"}
"tool_choice": {"type": "tool", "name": "get_customer"}
"tool_choice": {"type": "none"}

The two-question method

Ask these in order. The first one settles more than half the questions.

1. Is a plain-text reply acceptable for this request?

  • Yes, text is fine: auto.
  • Text is the only thing wanted, with no tool calls: none.
  • No, a tool must be called: go to question 2.

2. Does it have to be one particular tool?

  • Yes, exactly this one: name the tool.
  • No, any of several could be right: any.

A quick test for question 1: if a program reads the result, text is not acceptable. If a person reads it, text usually is.

Three checks before you commit

Is it forced on this request, or on every request?

tool_choice is sent with each request, so you can change it from one turn to the next. If a tool is forced on every turn, the agent can never finish: with any it can't give a final text answer, and with a named tool it calls the same tool for ever. Force a tool only on the turns that need one, then go back to auto.

What happens when the input doesn't fit the forced tool?

Claude still has to fill in that tool's fields, so it invents values. An instruction to "leave the fields empty" doesn't reliably stop this. Give Claude an honest alternative: a second tool such as reject_document, with tool_choice set to any.

Is a prompt instruction being offered as the fix?

An instruction such as "always look the customer up first" makes the behaviour likely. tool_choice makes it certain. When a question says something must always happen, the instruction is the wrong answer.

Why the wrong answers are tempting

Tempting choiceWhy it feels rightWhy it's wrong
any for a fixed first stepIt sounds like the strictest setting.It forces a tool call but not which one, so the agent can still start with the wrong tool.
auto plus an instructionIt's flexible, and the instruction says what to do.Claude can still reply in text or pick another tool.
A named tool on every requestIt guarantees the structure.Inputs that don't fit get invented values, and the agent can never move on.
none with "return JSON in your reply"It still asks for structure.Nothing enforces the schema, so the structure isn't guaranteed.

The three questions you met in the practice sets

Three extraction tools, document type unknown, Claude sometimes replies in text

Text isn't acceptable. Any of the three tools could be right. Answer: any.

The agent must look the customer up before anything else

Text isn't acceptable on the first turn. It must be one particular tool. Answer: name get_customer on the first request, then return to auto.

The invoice tool is forced, and non-invoices get invented values

A program reads every result, so text isn't acceptable and auto is out. The input doesn't always fit the forced tool. Answer: add a reject tool and use any.

Two side effects worth knowing

  • With any or a named tool, Claude goes straight to the tool call. It doesn't write any explanation first.
  • Extended thinking works only with auto and none. You can't force a tool while thinking is on.

Q9 Fix the design

tool_choice is fixed on a book_appointment tool. Some messages aren't booking requests at all, and Claude books made-up appointments for them. A program reads every result. What is the best fix?

  1. Keep the booking tool forced, and tell Claude to leave the fields blank for other messages
  2. Set tool_choice to auto, and accept a text reply whenever the message isn't a booking
  3. Add a second tool for messages that aren't bookings, and set tool_choice to any
  4. Set tool_choice to none, and ask Claude to describe the booking details in its reply
Show answer
C. A forced tool has to be filled in even when the input doesn't fit, so Claude invents values. Give it an honest second tool and use any. auto would allow text, which the program can't read.
Q10 Fix the design

An agent has tool_choice set to any on every request. It works through its tools correctly, but it never gives the customer a final answer. What is the best fix?

  1. Keep any on every turn, and add an instruction telling Claude to stop when it is done
  2. Keep any on every turn, and raise the token limit so Claude has room to finish
  3. Switch every turn to none, so that Claude always answers the customer in plain text
  4. Force a tool only on the turns that need one, and use auto on all the others
Show answer
D. With any, every response has to be a tool call, so a final text answer is impossible. Force a tool only where one is required.
