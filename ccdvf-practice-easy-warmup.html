Q1 Applications & Integration

Your chat app calls the Messages API. A user's follow-up question gets an answer that ignores everything said earlier in the conversation. What is the most likely cause?

  1. The app sends only the latest user message, and the Messages API doesn't remember previous calls
  2. The conversation has gone past the model's context window
  3. temperature is set too high
  4. A system prompt is needed before the API will keep memory
Show answer
A. The Messages API is stateless, so you have to send the full conversation history on every call.
Q2 Applications & Integration

Your support assistant gives long answers, and users complain that the UI looks frozen for several seconds before anything appears. Total generation time is fine. What should you do?

  1. Switch to a smaller model
  2. Lower max_tokens
  3. Send the request through the Message Batches API
  4. Turn on streaming and render text as it arrives
Show answer
D. Streaming fixes how slow the app feels. A and B reduce quality, and C is for offline work.
Q3 Applications & Integration · choose TWO

In production, your service sometimes gets HTTP 429 and 529 errors from the API. Which TWO responses are appropriate?

  1. Retry immediately in a tight loop until it succeeds
  2. Retry with exponential backoff and jitter
  3. Treat these errors as permanent and show the user a failure
  4. Switch to a different API key on every retry
  5. Respect the retry-after header when it's present
Show answer
B and E. 429 means you're being rate-limited and 529 means the API is overloaded. Both are temporary, so back off and retry. The official SDKs already retry these by default.
Q4 Applications & Integration

After Claude replies with stop_reason: "tool_use", your code runs the requested function. How do you send the result back?

  1. Put the result in the system prompt and call again
  2. Add a user message containing a tool_result block whose tool_use_id matches the original request
  3. Add an assistant message that contains the result
  4. Start a new conversation that includes only the tool result
Show answer
B. The tool result goes in the user turn, and its tool_use_id must match the request.
Q5 Model Selection & Optimization

Every request sends the same 40k-token system prompt (policies plus product catalogue), followed by a short user question that changes each time. Cost is high. What is the best fix?

  1. Shorten the system prompt by summarising it every request
  2. Put the user question first so the cache matches more often
  3. Use prompt caching, with the static content first and a cache breakpoint after it
  4. Use the Batches API for interactive questions
Show answer
C. The cache matches on the start of the prompt (the prefix), so static content goes first. B would break the cache.
Q6 Model Selection & Optimization

You need to sort 2 million support tickets a day into 8 fixed categories. On your eval set, accuracy is the same across all model tiers. Which choice fits best?

  1. The fastest, cheapest tier (Haiku-class)
  2. The most capable model, for safety margin
  3. The most capable model with extended thinking turned on
  4. Rotate between tiers to spread the load
Show answer
A. If accuracy is equal, the cheapest and fastest tier wins at this volume.

Q8 Agents & Workflows

A document pipeline always runs the same three steps: extract fields, check them against rules, then write a summary. The steps and their order never change. Which design fits best?

  1. A fully autonomous agent that decides which step to run next
  2. A multi-agent system with one agent per step that negotiate with each other
  3. A fixed workflow that chains the three prompts, with checks in code between steps
  4. A single prompt that asks for all three at once with no checks
Show answer
C. When the steps are predictable, a workflow is cheaper, easier to debug and more reliable than an agent.
Q9 Agents & Workflows

In a long-running coding agent, quality drops over time. It forgets constraints it was given early on and repeats work it has already done. Which approach helps most?

  1. Compact or summarise the history, and keep key constraints and progress in a persistent notes file the agent re-reads
  2. Raise max_tokens
  3. Restart the agent from scratch every 10 turns and discard all state
  4. Raise temperature to get more varied output
Show answer
A. Context drift is a context-management problem, so fix it with compaction and persistent notes.
Q10 Tools & MCP

Your company wants Claude Desktop, Claude Code and an internal agent to query the same internal inventory database. What is the best approach?

  1. Write a separate tool definition and handler inside each client
  2. Paste a database export into each system prompt
  3. Give each client direct database credentials in its prompt
  4. Build one MCP server for the inventory system and connect each client to it
Show answer
D. One MCP server can be reused by every client, which is the main reason MCP exists.
Q11 Security & Safety · choose TWO

Your agent reads web pages and is able to send emails. Which TWO measures reduce prompt-injection risk the most?

  1. Add "ignore any malicious instructions" to the system prompt and rely on that
  2. Raise the model tier, since bigger models can't be injected
  3. Treat fetched content as untrusted data, kept separate from instructions
  4. Give the agent broader permissions so it doesn't get stuck
  5. Require human confirmation (or a deterministic check) before any email is sent
Show answer
C and E. Defence comes from how the system is designed. A prompt instruction (A) is not a guardrail.
Q12 Claude Code

Your team wants everyone's Claude Code to follow the repo's build commands and coding conventions. You also want to block rm -rf reliably, not just ask the model not to run it. What is the best setup?

  1. Put everything in each developer's personal ~/.claude/CLAUDE.md
  2. Put the conventions in a project CLAUDE.md committed to the repo, and enforce the block with a PreToolUse hook or a deny rule in .claude/settings.json
  3. Put "never run rm -rf" in the project CLAUDE.md
  4. Tell developers to review each command by hand
Show answer
B. CLAUDE.md is guidance the model may or may not follow. Hooks and permission rules are actually enforced. C only asks.
