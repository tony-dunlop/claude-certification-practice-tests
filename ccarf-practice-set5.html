Scenario 1 Questions 1–5

Structured data extraction

You're designing a system that uses Claude to pull structured data out of documents such as invoices and contracts. The output is checked against a JSON schema and passed to downstream systems. Accuracy has to stay high, including on unusual documents.

Q1 Tool Design & MCP Integration

tool_choice is fixed on the invoice extraction tool. When a document turns out not to be an invoice, Claude still fills in the invoice fields with invented values. The pipeline needs a machine-readable result for every document. What is the best fix?

  1. Set tool_choice to auto, so Claude extracts invoices and replies in text for anything else
  2. Keep the extraction tool forced, and add an instruction to leave every field empty for non-invoices
  3. Add a second tool for rejecting a document, and set tool_choice to any for every request
  4. Set tool_choice to none, and ask Claude to return the extraction as JSON in its text reply
Show answer
C. The pipeline needs a structured result for every document, including "this isn't an invoice". Two tools with any gives Claude an honest way to say that. Forcing the extraction tool makes it describe an invoice that isn't there, and auto allows plain text the pipeline can't read.
Q2 Prompt Engineering & Structured Output

The schema has a contract end date field. Some contracts give no date, only wording such as "twelve months from signing". Claude works out a date, and it is sometimes wrong. What is the best schema change?

  1. Add a field for the wording as written, beside a date field that may be null
  2. Keep the single date field, and tell Claude to work the date out as carefully as possible
  3. Keep the single date field, and reject any contract that doesn't state an exact end date
  4. Change the date field to free text, and let downstream systems interpret whatever was written
Show answer
A. Keeping the original wording preserves what the contract actually says. A date that can be null stops a calculated guess being stored as a fact.
Q3 Prompt Engineering & Structured Output

On contracts of more than a hundred pages, a single extraction pass regularly misses clauses in the middle of the document. What is the best redesign?

  1. Extract from the whole document twice, then keep the result that has more fields filled
  2. Extract from the first and last twenty pages only, since key terms usually appear there
  3. Extract from the whole document once, with an instruction to pay attention to the middle
  4. Extract from each section separately, then merge the results and check them for conflicts
Show answer
D. Attention thins out over a very long document, most of all in the middle. Section-by-section passes give each part full attention, and the merge step catches conflicts between them.
Q4 Prompt Engineering & Structured Output

Human reviewers spend most of their time hunting through each document to confirm the extracted values. Which change to the output would speed them up the most?

  1. Return each value with a confidence score from one to ten, set by Claude itself
  2. Return each value with the page number and the exact wording that it was taken from
  3. Return each value twice, from two separate runs, so that reviewers can compare them
  4. Return each value with a short explanation of why Claude believes that it is right
Show answer
B. A page number and a quote let a reviewer confirm a value in seconds. A confidence score or an explanation still leaves them searching the document.
Q5 Context Management & Reliability

You're about to send 100,000 archived documents through the Message Batches API with a new extraction prompt. What should you do first?

  1. Run a sample of a few hundred first, fix what fails, then submit the full set
  2. Submit the full set at once, then resubmit whichever documents come back with errors
  3. Split the full set into ten equal batches, then submit all of them at the same time
  4. Submit the full set through real-time calls, then watch the first results as they arrive
Show answer
A. A sample run finds prompt and schema problems while they are cheap to fix. Finding them after the full run means paying for it twice.
Scenario 2 Questions 6–10

Code generation with Claude Code

Your team uses Claude Code to build features in a large existing codebase. You're deciding how it's configured and how developers should work with it.

Q6 Claude Code Configuration & Workflows

A set of rules about database migrations matters only when someone works in the migrations folder. The team wants those rules to use no context at any other time. Where should they go?

  1. In the root CLAUDE.md, under a heading that names the migrations folder
  2. In a rule file with no path pattern, alongside the team's other rule files
  3. In each developer's personal CLAUDE.md, under a heading for this project only
  4. In a rule file whose path pattern matches the migrations folder only
Show answer
D. A rule with a path pattern loads only when Claude works on matching files. A rule with no pattern is loaded in every session, the same as CLAUDE.md.
Q7 Claude Code Configuration & Workflows

One developer wants a local build command to run without an approval prompt, on their own machine and in this project only. Where should that permission go?

  1. In .claude/settings.json, which applies to everyone on the project and is committed
  2. In .claude/settings.local.json, which applies to them in this project and isn't committed
  3. In the project's CLAUDE.md, as an instruction saying the command needs no approval
  4. In the managed settings file, which applies to everyone in the organisation
Show answer
B. settings.local.json is personal to that developer in that project and stays out of version control. The shared settings file would change the permission for the whole team.
Q8 Claude Code Configuration & Workflows

The team's code formatter has to run after every file edit that Claude makes, with no exceptions. Which mechanism should enforce that?

  1. A line in CLAUDE.md that tells Claude to run the formatter after every edit
  2. A skill that developers invoke to run the formatter whenever they remember to
  3. A hook that runs the formatter automatically after every file edit that Claude makes
  4. A rule file that reminds Claude about formatting whenever it opens a source file
Show answer
C. Something that must happen every time belongs in a hook, which runs as code. Instructions and rules are followed most of the time, not every time.
Q9 Context Management & Reliability

A developer keeps one Claude Code session open all day and works through several unrelated tasks in it. By the afternoon, Claude is mixing up details from earlier tasks. What is the best habit to change?

  1. Start a fresh session for each unrelated task, and carry over only what the next one needs
  2. Keep one session for the whole day, and remind Claude of the current task every few turns
  3. Keep one session for the whole day, and ask Claude to ignore everything from earlier tasks
  4. Start a fresh session only when Claude makes an error, and continue in it until the next
Show answer
A. Leftover context from earlier tasks competes with the current one. A fresh session keeps the context for the task in hand.
Q10 Claude Code Configuration & Workflows

A developer wants Claude Code to work on two independent features at the same time, without one piece of work overwriting the other's files. What is the best setup?

  1. Run two sessions in the same folder, and tell each one which files to leave alone
  2. Run one session, and ask Claude to switch between the two features after each change
  3. Run two sessions in separate git worktrees, so each has its own copy of the files
  4. Run two sessions in the same folder, and commit after every edit to avoid any clashes
Show answer
C. Separate worktrees give each session its own files, so neither can overwrite the other. Sharing one folder relies on both sessions staying out of each other's way.
Scenario 3 Questions 11–15

Multi-agent research system

You're designing a research system in which a coordinator agent hands work to specialised subagents: one searches the web, one analyses documents, one combines the findings and one writes the report. Each subagent runs with its own separate context.

Q11 Agentic Architecture & Orchestration

You're deciding what the coordinator should put in the brief it gives each subagent. Which contents lead to the most useful results?

  1. The full conversation so far, so the subagent can work out for itself what is needed
  2. The goal, what is already known, the format to return, and where the task should stop
  3. A one-line topic, so the subagent is free to decide the scope and the format
  4. The coordinator's system prompt, so the subagent follows exactly the same rules and role
Show answer
B. A subagent starts with nothing but its brief. It needs the goal, the starting point, the format and the limits. The whole conversation buries those in noise.
Q12 Agentic Architecture & Orchestration

The system runs each stage once: search, analyse, combine, write. Reports often miss an angle that a human researcher would have gone back to look for. What is the best change?

  1. Have the coordinator accept the first set of findings, and note in the report that it may be incomplete
  2. Have the coordinator run every search twice at the start, so that gaps are less likely to appear
  3. Have the report writer fill any gaps from general knowledge, in the same style as the rest
  4. Have the coordinator check the combined findings for gaps, and send follow-up tasks for what is missing
Show answer
D. A single pass can't know what it missed. Checking the result and sending follow-up tasks is how the coordinator closes the gaps.
Q13 Context Management & Reliability

Two sources give different figures for the same statistic. On inspection, the figures come from different years. How should the system handle cases like this?

  1. Record the date of each figure with its source, so differences over time can be told apart
  2. Keep the figure from the more recent source, and drop the older one from the findings
  3. Keep the average of the two figures, and cite both of the sources next to it
  4. Record the figure that appears in more sources, and treat the other one as an error
Show answer
A. Two figures from different years may both be right. Recording the date lets the report show a change over time and not a false contradiction.
Q14 Tool Design & MCP Integration

The document-analysis subagent needs to work with a store of several hundred internal reports. It currently spends many tool calls finding out what exists. How should the store be offered to it?

  1. Expose one tool that returns every report in full, so the agent has everything at once
  2. Expose one tool for each report, so the agent can call the one it needs by name
  3. Expose the report catalogue as MCP resources, so the agent can see what exists before fetching
  4. Expose the store through Bash commands, so the agent can list and open the files itself
Show answer
C. Resources let the agent see what is available without spending tool calls to find out. One tool per report doesn't scale, and returning everything fills the context.
Q15 Context Management & Reliability

A full research run takes about two hours. When something crashes part-way through, all the work so far is lost and the run starts again. What is the best design change?

  1. Have the coordinator restart the whole run from the beginning, with a longer time limit set
  2. Have each agent save its progress to a file, and have the coordinator resume from those files
  3. Have the coordinator keep all progress in its own conversation, and summarise it more often
  4. Have each agent work on a smaller, faster model, so runs finish before a crash can happen
Show answer
B. Progress saved outside the conversation survives a crash. Progress held only in the coordinator's context is lost along with it.
