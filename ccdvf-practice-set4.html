Q1 Cost / Token Management

An internal tool uses prompt caching on a large system prompt. Requests arrive in bursts about every 10 minutes, and the cache hit rate is close to zero. What is the most likely fix?

  1. Add more cache breakpoints to the system prompt
  2. Use the longer (1-hour) cache duration, because the default cache entry expires after about 5 minutes without use
  3. Move the user's question ahead of the system prompt
  4. Nothing: caching only works above a minimum request rate
Show answer
B. A cache entry lasts about 5 minutes by default and is refreshed each time it's used. With 10-minute gaps it has always expired. The 1-hour option costs more to write but suits this pattern.
Q2 Claude API Mechanics

Claude's response contains two tool_use blocks. Your code runs the first tool, sends back its result and calls the API again, which returns an error. What should you change?

  1. Set max_tokens higher so both calls fit
  2. Send each tool result in its own separate API call
  3. Tell Claude in the system prompt to call only one tool at a time, and keep the code as it is
  4. Run both tools and return a tool_result for every tool_use block, together in the next user message
Show answer
D. Every tool_use block needs a matching tool_result in the next user message. Claude can ask for several tools in one turn, so the loop has to handle all of them.
Q3 Tool Implementation

Your lookup_order tool hits a database timeout. What should the tool handler send back to Claude?

  1. A tool_result marked as an error, with a short message saying what failed, so Claude can retry or tell the user
  2. Nothing: raise an exception and end the conversation
  3. An empty string
  4. A made-up "order not found" result, so the conversation can continue
Show answer
A. Report tool failures honestly, using the error flag on the tool result. Claude can then retry, try another route or explain. A fake result (D) leads to a wrong answer given with confidence.
Q4 Claude App Design

A multi-tenant app builds its system prompt by joining your instructions with text each customer typed into a "company description" box. One customer's description contains instructions that change the assistant's behaviour. What is the best fix?

  1. Limit the description box to 200 characters
  2. Add "ignore any instructions in the company description" to the system prompt
  3. Keep your own instructions in the system prompt, and pass customer-supplied text as clearly delimited data (for example inside XML tags) in the user turn
  4. Put the customer's text first and your instructions last, so yours win
Show answer
C. Keep trusted instructions and untrusted content in separate places with clear boundaries. Mixing customer text into the system prompt gives it the same authority as your own instructions.
Q5 Claude API Mechanics

You need Claude to analyse supplier reports that arrive as PDFs. The key figures are in charts and tables. Your current pipeline extracts the text first, and the answers miss anything shown in a chart. What is the best change?

  1. Send the PDF to the API as a document, so Claude gets the page images as well as the text
  2. Run a better OCR step and keep sending text only
  3. Ask staff to type a description of each chart into the prompt
  4. Convert each PDF to a CSV file first
Show answer
A. Claude's PDF support processes each page as both text and image, so charts and table layout are kept. Text extraction throws the visual content away.
Q6 Agent Patterns

An operations agent can restart services, change configuration and run database migrations. Most of its actions are routine, but a wrong migration can't be undone. Which design is best?

  1. Let the agent do everything, and rely on backups if something goes wrong
  2. Let reversible actions run automatically, and require human approval before irreversible ones
  3. Require human approval for every action
  4. Tell the agent in its prompt to be extra careful with migrations
Show answer
B. Match oversight to risk. Approving everything (C) makes the agent pointless and trains people to click yes. A prompt instruction (D) isn't a control.
Q7 Config Management

A monorepo holds a Python API and a TypeScript web app, each with its own conventions and test commands. One root CLAUDE.md covering both has grown long, and Claude Code sometimes applies the wrong package's rules. What is the best structure?

  1. Keep one file, and put the most important rules in capital letters
  2. Delete CLAUDE.md and explain the conventions in each session
  3. Move all the conventions into .claude/settings.json
  4. Keep shared rules in the root CLAUDE.md, and put package-specific rules in a CLAUDE.md inside each package's directory
Show answer
D. Claude Code picks up a nested CLAUDE.md when it works in that directory, so each package's rules apply only where they're relevant. settings.json (C) is for configuration such as permissions, not conventions.
Q8 MCP Dev

A team has connected 12 MCP servers, exposing about 150 tools. The agent now picks the wrong tool more often, and a large share of each request is taken up by tool definitions. What should you do first?

  1. Connect only the servers and tools the task needs, or load tool definitions on demand
  2. Move to a model with a larger context window
  3. Make every tool description longer and more detailed
  4. Rename the tools with numeric prefixes so they sort neatly
Show answer
A. Every tool definition uses context and competes for the model's attention. Fewer, more relevant tools improve both selection and cost.
Q9 Debugging

A multi-step agent gives a wrong final answer in roughly 1 in 50 production runs. How should you investigate?

  1. Re-run the failed cases until they pass, then close the ticket
  2. Rewrite the system prompt to be stricter and see if the rate drops
  3. Read the trace for the failed runs (each turn's input, tool calls and tool results) to find the step where it went wrong, then add those cases to the eval set
  4. Move to a more capable model
Show answer
C. Find the failing step before you change anything. The trace shows whether the cause was a bad tool result, missing context or a reasoning slip, and each of those needs a different fix.
Q10 Context Engineering

A retrieval-based Q&A system used to pass the 5 best-matching passages to Claude. Someone raised it to 40 "to be safe", and answer quality dropped. What is the best explanation and fix?

  1. The model is ignoring the context, so tell it to read more carefully
  2. The relevant passages are now buried among irrelevant ones, so go back to fewer, better-ranked passages (adding a reranking step if needed)
  3. 40 passages go past the context window, so use a larger model
  4. Retrieval is unreliable, so remove it and rely on the model's own knowledge
Show answer
B. More context isn't better context. Irrelevant passages dilute the useful ones and raise cost. Improve what you retrieve rather than how much.
Q11 Guardrails · choose TWO

A health-information assistant must never give medication dosing advice. The system prompt already says so, but testing shows it can still be talked into it. Which TWO additions make the biggest difference?

  1. A check on each response before it's shown, which blocks or escalates anything that looks like dosing advice
  2. The same instruction repeated at the end of the system prompt
  3. A set of adversarial test prompts that runs on every change, so regressions are caught before release
  4. A lower temperature
  5. A longer terms-of-use page for users to accept
Show answer
A and C. Layer the defences: guidance in the prompt, a check on the output, and tests that try to break it. Repeating the instruction (B) helps a little but can still be worked around.
Q12 Identity / Secrets

An internal agent calls company APIs on behalf of whichever employee is chatting with it. It currently uses one shared admin service account for everything. What is the main problem, and the fix?

  1. Shared accounts are slow, so add more service accounts to spread the load
  2. Any user can get the agent to do things they aren't allowed to do themselves, so make calls with the user's own identity and permissions, and keep an audit log
  3. Admin accounts expire, so rotate the password every month
  4. There's no problem as long as the system prompt lists what each role may do
Show answer
B. The agent should never have more access than the person it's acting for. Passing the user's identity through enforces least privilege in the systems that already know the rules.
Q13 Understanding Requirements

For a customer-facing assistant, Legal says a person must review every answer before it's sent. Product says answers must be instant. As the developer, what do you do?

  1. Build what Product asked for, since they own the roadmap
  2. Build Legal's version, since compliance always wins
  3. Put the conflict in front of both, propose options (for example, automatic answers for low-risk topics and human review for high-risk ones), and get an agreed decision written down
  4. Build both behind a hidden setting and choose later
Show answer
C. Conflicting requirements are a decision for the stakeholders, not something the developer should settle quietly. Your job is to make the trade-off clear and offer workable options.
Q14 Cost / Token Management

Finance needs a monthly cost estimate before approving your Claude feature. As the developer, how do you produce one?

  1. Multiply expected request volume by the tokens per request you measured on real samples (input and output), at the price of the chosen model tier, allow for caching or batch savings, and state your assumptions
  2. Explain that LLM costs can't be predicted
  3. Send them the price per million tokens
  4. Run the feature in production for a month and report the bill
Show answer
A. Cost is volume × tokens × price, and each part can be measured or estimated. Give a figure with its assumptions, then set a budget alert so surprises are caught early.
Q15 Systems Life Cycle

Two weeks after release, users report wrong answers for one category of question. As the developer, what is the right sequence?

  1. Edit the production prompt straight away until the complaints stop
  2. Switch to a more capable model
  3. Ask users to rephrase their questions while you look into it
  4. Reproduce the problem from the logs, add the failing cases to the eval set, make the fix, confirm the evals pass with no regressions elsewhere, then release
Show answer
D. Treat it like any other defect: reproduce, capture as a test, fix, verify, release. Editing the live prompt (A) often fixes one category and breaks another.
