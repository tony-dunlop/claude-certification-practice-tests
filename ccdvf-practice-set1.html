Q1 Applications & Integration

Prompt caching on a long system prompt has a cache hit rate above 90%. After a deploy that only added one new tool to the tools array, the hit rate drops to zero for a few minutes and then recovers. Why?

  1. Adding a tool disables caching for 5 minutes as a safety measure
  2. Every deploy creates a fresh API session, which clears all caches
  3. Tools come before the system prompt in the cached prefix, so changing them invalidates the cached system prompt too
  4. The system prompt's cache breakpoint must be re-declared whenever tools change
Show answer
C. The cache is built in the order tools → system → messages. Changing anything early in that order invalidates everything after it, and the cache rebuilds on the next requests.
Q2 Applications & Integration

You submit 5,000 requests through the Message Batches API. When you process the results, about 3% of the summaries are attached to the wrong source documents. What is the most likely cause?

  1. Your code assumes results come back in the order you submitted them, instead of matching each one by custom_id
  2. The batch went past the 24-hour window and some results were regenerated
  3. Batches are processed by different model versions, and some outputs are mixed up
  4. Prompt caching across batch requests is leaking context between them
Show answer
A. Batch results can come back in any order. Always match each result to its request using custom_id.
Q3 Applications & Integration

Your app streams responses that include tool calls. Sometimes the tool's input fails to parse as JSON. Your code calls JSON.parse on every input_json_delta event as it arrives. What should you change?

  1. Turn streaming off whenever tools are enabled
  2. Wrap each parse in a try/catch and skip the fragments that fail
  3. Set max_tokens higher so the JSON is never split
  4. Collect the partial JSON strings for that content block and parse them once at content_block_stop
Show answer
D. Each delta is a fragment of JSON (for example {"order_id": "12) and is almost never valid by itself. Skipping the fragments that fail (B) throws away the tool input. Join the fragments for the block, then parse once when the block ends.
Q4 Applications & Integration

A structured-extraction call sometimes returns JSON that is cut off partway through. The JSON is valid every other time. Which check should your code make first?

  1. Run a JSON repair library on every response
  2. Check whether stop_reason is max_tokens and handle it (raise the limit, or retry/continue), rather than parsing anyway
  3. Lower temperature to make the output deterministic
  4. Switch to a larger model, which produces shorter JSON
Show answer
B. JSON that's cut off is the classic sign of hitting max_tokens. Check stop_reason before parsing. A repair library (A) hides missing data.
Q5 Applications & Integration

You use extended thinking together with tool use. On the second turn of a tool loop, the API returns an error. Your code rebuilds the assistant message from only the tool_use block, to save tokens. What should you change?

  1. Send the assistant's previous content back unchanged, including the thinking blocks and their signatures, along with the tool_use block
  2. Turn off thinking on every turn after the first
  3. Move the thinking text into the system prompt
  4. Set budget_tokens higher than max_tokens
Show answer
A. In a tool loop with thinking, the thinking blocks have to be returned exactly as received. D is invalid: budget_tokens must be less than max_tokens.
Q6 Applications & Integration

A single-page web app calls the Claude API directly from the browser using an API key in the JavaScript bundle. Security has flagged it. What is the right fix?

  1. Obfuscate the key and rotate it every month
  2. Restrict the key using CORS and an allowed-origins list
  3. Send calls through your own backend, which holds the key, authenticates users and enforces per-user limits
  4. Store the key in localStorage after the user logs in
Show answer
C. Any secret sent to the browser can be read by anyone using the app. CORS (B) is enforced by browsers, not by the API, so it doesn't stop someone using a leaked key directly.
Q7 Model Selection & Optimization

Every night you summarise 50,000 documents. They all share an identical 20k-token instructions block. Results are needed by 9 a.m., and the job starts at 10 p.m. What is the cheapest correct approach?

  1. Run synchronous calls with prompt caching
  2. Use the Message Batches API. Prompt caching can't be used with batches
  3. Run synchronous calls on the smallest model with no caching
  4. Use the Message Batches API and also use prompt caching on the shared instructions block
Show answer
D. The batch discount and the prompt-caching discount can be combined. The overnight deadline fits batch processing.
Q8 Model Selection & Optimization

A compliance team wants a report on ad-hoc questions within 2 hours of asking. Volume is low (about 30 requests a day). An engineer suggests the Batches API "because it's half price." What is the main problem with that?

  1. Batch processing is only guaranteed within 24 hours, so it doesn't meet a hard 2-hour requirement
  2. The Batches API needs at least 1,000 requests
  3. The Batches API doesn't support the larger model tiers
  4. Batch results can't be streamed, so the reports will be lower quality
Show answer
A. Batches often finish much sooner, but only the 24-hour window is guaranteed. A hard 2-hour requirement needs real-time calls.
Q9 Model Selection & Optimization · choose TWO

An agent's cost per task has tripled since launch. Traces show the same 30k tokens of reference documents are re-sent on every turn, and most turns are simple file reads and lookups. Which TWO changes should you make first?

  1. Raise temperature so the agent reaches answers faster
  2. Cache the static reference documents in the prompt prefix
  3. Remove the reference documents and rely on the model's training data
  4. Send the simple lookups to a cheaper model tier, and keep the expensive model for planning and reasoning
  5. Turn on extended thinking for every turn
Show answer
B and D. Caching removes the cost of re-sending the same input, and routing sends the simple work to the cheaper tier. E would raise costs further.
Q10 Agents & Workflows

A research agent has to investigate 6 independent sub-topics, and each one needs a lot of browsing. When one agent does all of it, the context fills up and the quality of the final synthesis drops. Which design addresses this best?

  1. Raise max_tokens on the single agent
  2. Truncate the oldest browsing results whenever the context is 80% full
  3. Have an orchestrator hand each sub-topic to a subagent with its own context, and have each subagent return a condensed summary for synthesis
  4. Run 6 completely separate agents with no orchestrator, and concatenate their raw transcripts
Show answer
C. Subagents keep their own contexts separate, and returning summaries keeps the orchestrator's context small. D gives you the same overflow problem again at the synthesis step.
Q11 Prompt & Context Engineering

You're building a Q&A feature over 3 long contracts (about 60k tokens in total). Which prompt layout follows Anthropic's guidance for long-context performance?

  1. The documents near the top, each wrapped in XML tags with source metadata, and the question and instructions at the end
  2. Question first, then the documents, then the question repeated
  3. The documents spread across several user turns, with the question in the system prompt
  4. A summary of each document instead of the full text, to save context
Show answer
A. Anthropic's guidance is long documents first and the query last, with each document in clearly tagged blocks.
Q12 Prompt & Context Engineering

A classification prompt includes 3 few-shot examples. In production, the model labels too many items with the category used in 2 of those examples. What is the best fix?

  1. Remove all the examples
  2. Add "do not overuse category X" in capital letters
  3. Raise temperature to spread out the predictions
  4. Use more varied, balanced examples that cover the edge cases, and state the decision criteria explicitly
Show answer
D. Examples that lean towards one category bias the output. Balance the examples and spell out the decision criteria, rather than shouting a rule.
Q13 Tools & MCP

Your agent has two tools: search_orders and search_customers. It often calls search_orders with a customer's name and gets no results. What is the best first fix?

  1. Force tool_choice to search_customers for every request
  2. Merge both into a single search tool with no parameters
  3. Rewrite both tool descriptions to say what each one searches, which inputs it accepts and when to use it rather than the other, with input schemas to match
  4. Add a retry loop that calls the other tool after an empty result
Show answer
C. Tool descriptions are the main way the model decides which tool to use. Forcing tool_choice (A) breaks the cases where search_orders is the right tool.
Q14 Tools & MCP

Your platform team wants to give 200 engineers access to an internal MCP server for the deployment system. Running it locally means everyone installs the server and holds their own copy of the credentials. What is the better setup?

  1. Host it as a remote MCP server over HTTP with proper authentication, so credentials stay on the server side
  2. Keep the local setup, and share the credentials through a team password vault
  3. Paste the deployment API docs into each engineer's CLAUDE.md and let Claude call the API with curl
  4. Package the server as a Claude Code plugin with a credentials file built in
Show answer
A. A single hosted server with per-user authentication means credentials are never handed out, and there's one copy to maintain.
Q15 Claude Code

Your organisation's managed settings deny Bash(curl:*). A developer adds Bash(curl:*) to allow in their .claude/settings.local.json and runs Claude Code with no extra flags. What happens?

  1. The local setting wins, because it's the most specific
  2. The managed deny wins, because managed settings have the highest priority and can't be overridden
  3. Claude Code asks the developer to choose between the two rules
  4. Whichever file was changed most recently wins
Show answer
B. Managed settings have the highest priority, and a deny rule beats an allow rule anyway.
