Scenario 1 Questions 1–5

Customer support resolution agent

You're designing an agent that resolves support tickets for an online retailer. It has tools to look up customers and orders, issue refunds, and escalate to a human. The target is to resolve 80% of tickets at first contact without a person stepping in.

Q1 Tool Design & MCP Integration

On every new ticket, the agent should look the customer up before it does anything else. Sometimes it starts with an order lookup or a text reply. Which tool_choice setup is best?

  1. Set it to any on every request, so that the agent always calls one of its tools
  2. Set it to the get_customer tool on the first request, then return it to auto for later turns
  3. Set it to auto on every request, and say in the prompt to look the customer up first
  4. Set it to none on the first request, so that the agent asks the customer for their details
Show answer
B. Naming a tool forces that exact call, which suits a fixed first step. After that, auto lets the agent choose. any forces a tool call but doesn't say which one.
Q2 Agentic Architecture & Orchestration

A customer's message contains three separate requests: a refund, a change of address and a delivery question. The agent deals with the first one and closes the ticket. What is the best change?

  1. Have the agent answer the first request, and ask the customer to raise the others as new tickets
  2. Have the agent pass any message with more than one request straight to a human agent
  3. Have the agent choose the most urgent request, resolve it fully, and close the ticket afterwards
  4. Have the agent list each separate request first, work through them all, then send one combined reply
Show answer
D. Customers often raise several things at once. Listing them first makes sure none is dropped, and a single reply saves the customer from chasing the rest.
Q3 Agentic Architecture & Orchestration

The order tool draws on three back-end systems. Each one returns dates and status codes in its own format, and the agent sometimes misreads them. What is the most reliable fix?

  1. Add a hook that runs after each tool call and converts the results into one consistent format
  2. Add a section to the system prompt that explains each back-end system's date and status formats
  3. Add a second model call after each tool call that rewrites the results into plain English
  4. Add few-shot examples to the prompt that show the agent reading each of the three formats
Show answer
A. A hook is code, so the conversion happens the same way every time, before the model sees the result. Explaining the formats in the prompt leaves the model to convert them, and it will sometimes slip.
Q4 Context Management & Reliability

Each order lookup returns more than 40 fields, and the agent uses about five of them. After several lookups the conversation is crowded and the agent's answers get worse. What is the best fix?

  1. Summarise the whole conversation after each tool call, so that earlier results take up less room
  2. Move the agent to a model with a larger context window, so that all the results fit
  3. Trim each tool result to the fields the task needs before it is added to the conversation
  4. Limit the agent to two order lookups per ticket, so that fewer results are ever added
Show answer
C. Most of each result is never used. Cutting it down at the source keeps the context for what matters and loses nothing the task needs.
Q5 Context Management & Reliability

A customer gives their name as John Smith, and the customer lookup returns three matching accounts. The agent currently carries on with the first one. What should it do?

  1. Have the agent choose the match with the most recent order, since that customer is most likely
  2. Have the agent ask the customer for another identifier, such as their email address or postcode
  3. Have the agent choose the first match returned, and confirm the name with the customer afterwards
  4. Have the agent run the lookup again with the same name, in case the results come back different
Show answer
B. Guessing between people with the same name risks showing or changing the wrong account. One more identifier settles it.
Scenario 2 Questions 6–10

Developer productivity with Claude

You're building an internal assistant with the Claude Agent SDK. It helps engineers explore unfamiliar codebases, understand legacy systems and automate routine tasks. It uses the built-in tools (Read, Edit, Write, Grep, Glob, Bash) and connects to MCP servers.

Q6 Tool Design & MCP Integration

An MCP server offers a code_search tool that understands symbols and references. Its description reads "Searches code". The agent keeps using the built-in Grep and gets poorer results. What is the best fix?

  1. Remove the built-in Grep tool from the agent, so the MCP tool is the only way to search
  2. Add a line to the system prompt saying the agent must never use Grep for code searches
  3. Rename the MCP tool to something longer, so that it sorts above Grep in the tool list
  4. Expand the MCP tool's description to say what it searches, what it returns and when to prefer it
Show answer
D. The description is what the model uses to choose a tool, and "Searches code" gives it no reason to prefer this one. Removing Grep takes away a tool that is still right for simple text searches.
Q7 Tool Design & MCP Integration

The assistant needs to read and comment on issues in the team's issue tracker. The tracker's vendor publishes a maintained MCP server that covers this. A developer proposes writing a custom MCP server for it. What is the best decision?

  1. Use the vendor's server, and build a custom one only for needs that it doesn't cover
  2. Build a custom server from the start, so the team controls every tool and its description
  3. Skip MCP for this, and have the agent call the tracker's API through Bash commands
  4. Use both servers side by side, so the agent can choose whichever tool works best
Show answer
A. A maintained server saves the team from building and looking after its own. Keep custom work for the gaps. Two servers with overlapping tools make it harder for the agent to pick the right one.
Q8 Agentic Architecture & Orchestration

You've defined three subagents for the assistant. The coordinator never hands work to them and does everything itself, even when the user asks it to delegate. What is the most likely cause?

  1. The subagents' descriptions are too short, so the coordinator can't tell which of them to choose
  2. The subagents' allowed tools include too many entries, so the coordinator refuses to start any of them
  3. The coordinator's allowed tools don't include the tool that starts subagents, so it can't delegate
  4. The coordinator's system prompt doesn't name the subagents, so they were never loaded into the session
Show answer
C. An agent can only use the tools it has been allowed. Without the tool that starts subagents it can't delegate, whatever the prompt or the user says.
Q9 Tool Design & MCP Integration

A developer wants to try an experimental MCP server in all of their own projects. Teammates shouldn't get it. How should they add it?

  1. Add it at user level, so it is available in their own projects and not shared
  2. Add it to each project's .mcp.json, and ask teammates not to use it until it's ready
  3. Add it to each project's .mcp.json, and leave that change uncommitted in every repository
  4. Add it to each project's CLAUDE.md, with a note explaining how the server should be started
Show answer
A. A user-level server follows the developer across projects and stays out of the repository. An uncommitted project file has to be repeated in every repository and is easy to commit by mistake.
Q10 Context Management & Reliability

An engineer asks the assistant how billing works in a large legacy codebase. It reads files more or less at random and runs out of context before it can answer. What is a better strategy?

  1. Read every file in the billing folder from top to bottom, then summarise what was found
  2. Read the largest files in the repository first, since they hold most of the logic
  3. Search for the word "billing", then read every file in which that word appears
  4. Search for the entry points first, then follow the calls and read only those files
Show answer
D. Following the path from the entry point reads what matters, in the order it runs. Reading whole folders or every match fills the context before the picture is clear.
Scenario 3 Questions 11–15

Claude Code for continuous integration

Your team is adding Claude Code to its CI pipeline. On every pull request it reviews the changes and posts comments, and a nightly job generates missing tests.

Q11 Claude Code Configuration & Workflows

The nightly job keeps generating tests for cases that the existing test suite already covers. What is the most effective fix?

  1. Give Claude a limit of five new tests per run, so that fewer duplicates can be created
  2. Give Claude an instruction to write only original tests, and to avoid repeating any others
  3. Give Claude the existing test files as context, so it can see which cases are already covered
  4. Give Claude a second pass over its own output, with a request to delete any duplicates
Show answer
C. Claude can't avoid repeating tests it hasn't seen. Showing it the existing tests is what makes "don't duplicate" possible.
Q12 Claude Code Configuration & Workflows

Each time a developer pushes a new commit to a pull request, the review bot posts all of its earlier comments again. What is the best fix?

  1. Delete all the earlier comments before each run, so the pull request shows only one set
  2. Pass in the earlier findings, and ask Claude to report only new or unfixed issues
  3. Run the review on the first commit only, and skip every later push to the branch
  4. Limit each run to the three most serious findings, so that fewer comments are repeated
Show answer
B. With the earlier findings in hand, Claude can tell what is new and what has been fixed. Deleting the old comments hides the history without stopping the repeats.
Q13 Claude Code Configuration & Workflows

The CI job has to run with nobody there to approve actions, but it shouldn't be able to do anything it likes on the build machine. How should permissions be set?

  1. Skip all permission checks for the job, since it runs inside a pipeline with nobody watching
  2. Leave the default prompts on, and have the pipeline answer yes to each one automatically
  3. Give the job full permissions, and tell Claude in the prompt which commands to avoid
  4. Allow only the specific tools and commands the job needs, and deny everything else in settings
Show answer
D. A pipeline can't answer prompts, so permissions have to be set in advance. Allowing only what is needed keeps the job working and limits the damage from a mistake or a malicious pull request.
Q14 Prompt Engineering & Structured Output

The review bot's severity labels are inconsistent. The same kind of issue is marked "critical" on one pull request and "minor" on another. What is the best fix?

  1. Define each severity level in the prompt, with a concrete code example of each
  2. Ask Claude in the prompt to apply severity levels carefully, and to be consistent between runs
  3. Remove severity levels from the output, and list every finding with the same weight
  4. Run each review three times, and use whichever severity level appears most often
Show answer
A. Concrete examples show where each level starts and ends. Asking for consistency doesn't tell the model what the levels mean.
Q15 Prompt Engineering & Structured Output

One category of review comment, unused imports, is wrong most of the time. Developers have started to distrust the bot's other comments, which are accurate. What should you do?

  1. Turn the whole review bot off until every category is accurate, then switch it back on
  2. Keep every category running, and add a note to each comment saying it may be wrong
  3. Turn that one category off while its prompt is improved, and keep the accurate categories running
  4. Keep every category running, and ask developers to mark each wrong comment as resolved
Show answer
C. One noisy category makes people distrust all the comments. Pausing only that one protects trust in the rest while it is fixed.
